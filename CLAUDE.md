   render nothing for it and leave a code comment `// TODO(content): ...`.
   Before finishing any task, search the codebase for `TODO`, `lorem`, `placeholder`,
   `example`, `XXX` and any number not found in CONTENT.md, and report what you find.

   generated by code. The full dataset stays local; it is used only to calibrate the quality limits
   (`scripts/calibrate_quality.py`).
4. **No brand logos or mascots** (Duolingo owl, NASA, SDAIA, KAUST, Mawhiba, etc.).
   Write organization names as plain text only.
5. **Claude writes all modules**, including `src/lib/vessels/` (space colonization),
   `src/lib/graph/` (pathfinding animation) and `src/lib/quality/` (image quality metrics).
   Every algorithm file starts with a short plain-English comment explaining how it works.
6. **Small changes.** One feature per commit, with a clear commit message. Briefly explain what
   you changed and why. Don't rewrite files I didn't ask about.
7. **No new dependencies** beyond the stack below without telling me why first.
8. **Don't touch** `public/CNAME` or `.github/workflows/` without asking.
9. **No secrets in the repo.** Check `.gitignore` before the first push.
10. Work on the `redesign` branch. Only `main` deploys. Never push to `main` unless I say so.

## Design system

```
--bg:        #0B0D12   near-black navy
--surface:   #12151C   cards / raised areas
--text:      #E8E6E1   off-white
--text-dim:  #9A9890   secondary text (must still pass WCAG AA on --bg)
--accent:    #F08A4B   fundus amber, the ONLY accent color
--glow:      #5CC8FF   cyan, used ONLY for vessels / graph edges inside the 3D scene
```

- IBM Plex Mono ONLY for standalone metrics: HCGCC headline numbers, timeline dates and training dates.
  Digits inside sentences, headings, bullets and the hero lines use the normal body/heading font.
- Reading width max ~720px. Generous spacing. Left-aligned text.
- Text contrast passes WCAG AA (4.5:1) everywhere.

**Banned:** gradients on text or backgrounds, glassmorphism/frosted cards, glowing card borders,
emoji in headings, custom cursors, cursor trails, typewriter effects, preloaders longer than 1s,
scroll-jacking, skill bars/percentages, auto-playing audio, "Coming soon" sections,
stock 3D models, parallax on body text.
Also banned everywhere: purple or any other gradients, gradient text, glow, glossy blobs, emoji,
a pill/badge or label above the headline, hype words, centered layouts, fake reviews/testimonials,
4-item feature grids, pill-shaped corners (2–4px radius max), Inter, stat banners,
tiny all-caps labels, icon boxes, cards, bouncing/bouncy animation.

**Main button:** the hero says what I do, and "View work" is the only filled button.
The three project objects in the hero may move (the one-bright-moment rule was dropped 2026-11-23).
Amber is for links, the main button and focus states only.

  (switch the three parts on to build the modeled FY2029 revenue).

Charts are SVG or canvas built from numbers in CONTENT.md only.

## 3D concept (phase v2): "Three objects find their projects"

One WebGL canvas fixed behind the home page. **All text stays real HTML; never render text
inside the canvas.** Objects are points and lines built in code (no models).

1. **Hero:** the three project objects sit in empty slots beside the name and turn slowly:
   Mizan's rising trend lines, the eye, and the Beyond the Streak bars (+23% vs +8%).
   The eye turns toward the cursor.
2. **Scroll:** each project row has an empty slot. As a row comes up the window, its object
   slides from the hero into that slot. Native scroll only; the page is never moved by script.
3. **Hover/focus a row:** Mizan's lines straighten, the pupil widens, the bars rise.
4. **Drag:** visitors can move any object anywhere (grab the middle) or spin it (grab the edge).
   Dragging never starts on a link or button. Scrolling sends every object back home.
5. **Over text** an object fades so the text reads as if the object were behind it.
6. **After the project list** the objects follow the visitor: each glides to a random spot
   with no text under it. There Mizan and Beyond the Streak glitch into another design every
   10–15 s (Mizan: trend lines / globe / 5%-false-alarm grid; Streak: bars / stacked $81M-$16M-$23M
   column / users-vs-bookings lines). The eye never changes.
7. **Idle:** after a few seconds without input, objects drift and turn very slowly.
   The eye squints while the pointer is over text and looks at whichever project is hovered
   (no blinking: Yousef removed it).
   **Give the eye a retina photo** to run the stage-1 quality gate in the browser: the three
   example photos sit beside it in the hero (drag one in, or tap it and it flies in), or drop
   your own. A panel beside the eye shows the verdict. Nothing is uploaded.
8. Later (not started): fly through the pupil onto the retina, Retina → Graph → Network.

## Performance and accessibility budgets

- HTML text renders first; the 3D island loads after first paint.
- LCP < 2.5s, CLS < 0.05 on Lighthouse mobile. Accessibility ≥ 95, SEO = 100.
- 3D JS ≤ 300 KB gzipped.
- Pixel ratio capped at 1.5. Pause the render loop when no object is on screen or the tab is hidden.
- **Mobile (<768px):** the eye only; below 960px the objects stay in the hero.
- **`prefers-reduced-motion`:** nothing turns on its own; objects only follow scrolling.
- Any model compressed (meshopt/Draco); textures KTX2 or WebP.
- Full keyboard navigation and visible focus states. Meaningful `alt` text.

## Codeforces data (phase v3)

Fetched **at build time** from the public API (`user.info`, `user.rating`, `user.status`)
for the handle in CONTENT.md and written to `src/data/codeforces.json`.
If the API fails, the build must **not** fail: fall back to the last committed JSON.
Never fetch Codeforces from the visitor's browser.
